# 会議議事録RAG 評価記録

実施日: 2026-10-03〜10-04 / 目的: 議事録検索(RAG)が「どのくらい正しく答え、どこで間違えるか」を数字で把握する。

## 評価の前提

- **対象**: ダミー議事録35件(2026年3〜9月、5種類の定例会議×7ヶ月)を103チャンクに分割して保存したもの
- **構成**: 質問をVoyage `voyage-4-lite`(1024次元)でベクトル化 → `match_meeting_minutes`で候補を最大10件(類似度0.25以上、期間指定あり)→ `rerank-3-lite`で採点し直し、**0.60以上**を最大5件 → ヒットした会議の**全段落**をClaude Haiku 4.5に渡して回答
- **日付の前提**: 実行時の「今日」は2026年10月。「先月」は9月、「今月」は10月(議事録なし)
- **実行方法**: APIに1問ずつ送信(間隔45秒、Voyage無料枠の制限対策)。**各回1回ずつ(n=1)**
- **採点**: 実施者(AI)が下記ルールで採点。質問・議事録とも同じAIが作成した

### 判定ルール

- 該当あり: ○=要点が正しく、引用した日付・タイトルが正解と一致 / △=要点は合っているが取りこぼしあり、または出典が一部ずれる / ×=間違い、または誤って「該当なし」
- 該当なし: ○=「該当する記録がありません」と答え、推測で内容を述べない / ×=関係ない議事録をこじつけて回答
- スコア: ○=1点、△=0.5点(12点満点)

### 1回目の主な不合格理由

- 1番・4番: 議事録を検索せず「メモ・TODO・家計簿・議事録のどれですか?」と聞き返しただけだった
- 10番: 7/10・8/15・9/10・9/15は正しく拾えたが、問題の始まりを「7月」と答えた(5/10のGW中のランチ時の遅れが最初)

## 1回目と2回目の間に行った修正

システムプロンプトと、`search_meeting_minutes`ツールの説明文を変更。

- 変更前: 「メモ・TODO・家計簿のどれを指しているか分からないときは推測せず、聞き返す」(議事録を追加する前に書いた指示がそのまま残っていた)
- 変更後: 「編集の対象が複数あって特定できないときだけ聞き返す。稼働率・売上・メニュー・設備・人員・クレーム・販促など業務に関する質問は、聞き返す前にまず`search_meeting_minutes`で検索する」
- ツール説明文に、記録されている話題(稼働率、メニュー、設備、人員、クレーム、販促など)を追記

## 分かったこと

1. **検索・リランキング・引用の部分は狙い通り機能した**。議事録検索が実行された質問は、2回目では「該当なし」を含めほぼすべて○だった。期間指定(先月・今月・月指定)も正しく動いた
2. **1回目の失敗の原因は検索精度ではなく、「どのデータを検索するか」の判断**だった。原因は、過去に書いたプロンプトの指示が新しい機能と衝突していたこと。機能を追加したら、既存の指示との矛盾がないかを見直す必要がある
3. 「該当なし」は、リランキングのスコア(しきい値0.60)による機械的な判定で働いた(7番・11番・12番)
4. 類似度(ベクトル検索の数値)は、このデータでは0.3〜0.7に圧縮され、絶対値で関連の有無を判定できない。リランキングのスコアで初めて分離できた(16個の質問で、関連ありは0.70以上、なしは0.52以下)

## 残っている課題・この評価の限界

- **10番(複数会議をまたぐ経緯の質問)は2回とも△**。5/10の議事録(「ランチタイムのオーダー処理に遅れ」と書かれ、「提供遅延」とは別の言い回し)を拾えなかった。どの段階で落ちたか(候補の10件に入らなかったのか、リランキングで0.60未満だったのか)は未調査
- **n=1で、AIの回答は毎回変わる**。1回目→2回目の改善は、原因(プロンプトの指示)が回答内容から説明できるものの、偶然の揺らぎを完全には除けない。同じ質問を複数回実行して安定性を見る必要がある
- **12問と少なく、質問と議事録を同じAIが作った**ため、実際の利用者の質問より解きやすい可能性が高い。数字は「このデータ・この質問での目安」であり、一般化できない
- 回答の最大長(`max_tokens`)は1024のままだが、今回の12問では途中で切れた回答はなかった

## 次にやるなら

2. 質問数を増やし、各質問を複数回実行して正答率の幅を見る
3. 実際の利用者に近い言い回し(略語、曖昧な質問、複数の話題を含む質問)の質問を追加する

## 追記(2026-10-05): 手動確認で見つかった問題と対応

評価の12問では見つからず、**実際に画面で試したときに発覚**した。「先月の議事録をまとめて要点5点教えて」に対し、9月の議事録(5会議・14チャンク)が実在するのに「記録されていないようです」と回答した。

- **原因**: 候補としては拾えていたが、「要点」「まとめ」には話題がないため、リランキングのスコアが全段落で0.34〜0.43となり、しきい値0.60で全除外された(「会議の決定事項と報告事項」のような言い換えでも最高0.56で0件)。日付の計算は正しかった。**関連度で絞る検索は、「期間全体を見たい」質問に構造的に向かない**
- **言い回しの問題**: 結果が空のとき、AIが「記録されていない」「会議が開催されていない」と断定した。実際は「関連する記録が見つからなかった」だけで、事実と異なる案内だった
- **対応**: 期間を指定して議事録をそのまま取り出す8つ目のツール`list_meeting_minutes`を追加(関連度の判定なし・ベクトル化なし、新しい順に最大12会議)。話題がある質問は従来の`search_meeting_minutes`、期間全体を見る質問は`list_meeting_minutes`、とプロンプトで使い分けを指示。空のときに存在しないと断定しないことと、複数会議をまとめるときも各項目に出典(日付・タイトル)を付けることもプロンプトに追加
- **確認結果(各1回)**:
  - 「先月の議事録をまとめて要点5点教えて」→ `list_meeting_minutes`を使い、9月の5会議を網羅した5点を、各項目に日付・タイトル付きで回答(初回は出典が付かなかったため、指示を強めて再確認)
  - 「今月の議事録の内容を教えて」→ 「10月分は登録されていません」と正確に回答(従来は検索経由の「該当なし」)
  - 「先月のクレームの傾向は?」→ 従来通り`search_meeting_minutes`が選ばれ、3つの苦情を日付・タイトル付きで回答(悪化なし)

### 学び

- **評価の質問セットに、この種類(期間まとめ型)がなかった**ため、12問で96%でも見逃した。評価セットは、実際の利用者が聞きそうな質問の種類を網羅できているかが重要で、**手で触って見つかった問題は質問表に追加していく**(今回の質問を13問目として加える)
- 検索(RAG)は「話題で探す」ためのもので、「期間・種類などの条件で取り出す」用途は別の経路(メタデータによる絞り込み)で扱う方が確実
